# Security

yamlreel turns a YAML spec into a video. A spec names files and URLs, so it is treated as untrusted input:

- Local images, pages, music and watermark logos must sit inside the spec's folder, the config folders, or a folder you allow with `--allow-path` (or `allow_paths` in your *user* config). Symlinks cannot escape.
- URL captures accept `http(s)` and in-folder `file://` only. Every request the captured page makes, including redirects and sub-resources, goes through the same check. By default only public internet unicast addresses are allowed (IPv6 in `2000::/3`). With `--allow-private-hosts`, loopback, private networks (RFC 1918), `100.64.0.0/10` (CGNAT, for example Tailscale) and IPv6 unique-local addresses are allowed too, but never the always-denied ones: link-local and cloud-metadata addresses (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::/32`, the GCP and Oracle IPv6 metadata addresses, `100.100.100.200`, `168.63.129.16`), `192.0.0.0/24`, `0.0.0.0/8`, and multicast, reserved and deprecated IPv6 forms (`::/96`, `fec0::/10`, `64:ff9b:1::/48`). Known cloud-metadata host names (such as `metadata.google.internal` and `instance-data`) are refused, and so are non-standard numeric hosts in spec URLs (`2130706433`, `0x7f.1`, `127.1`, `0177.0.0.1`). Host names are converted with IDNA first, so fullwidth digits and ideographic full stops are judged as the ASCII address they stand for. Every address a name resolves to must pass, and addresses wrapped in IPv4-mapped, 6to4, Teredo or NAT64 forms are judged by the IPv4 address inside. Every http(s) request, including each redirect hop, goes through the pinning proxy below. A plain-HTTP request gets its own checked upstream connection, and an HTTPS tunnel is opened only to the address checked for its CONNECT host, so no hop can reach an address that was not checked. `file://` requests are checked against the allowed folders instead.
- `allow_paths`, `allow_private_hosts`, `chromium_path`, `font_dir` and `voice_server` cannot be set by a spec or a project config, only by the user config or the command line.
- The user config (including its pre-0.2 location, still read until 0.3.0) is the only file that can set trusted keys.
- URL captures run through a small local pinning proxy: each host name is resolved once, every address is checked, and the browser is connected to that exact address, so DNS rebinding cannot swap in an internal address after the check. If the policy refuses any request of a capture, including a redirect hop or a sub-resource such as an image, the capture fails with an error instead of rendering a partial page; a host name that merely does not resolve, or that a DNS ad blocker answers with `0.0.0.0` or `::`, does not fail it (it is still never connected to). The proxy's own record decides this, never anything a site sends. Chromium is started with its WebRTC policy set to `disable_non_proxied_udp`, so WebRTC cannot reach the network around the proxy.
- Music files are only read as real audio containers (wav, mp3, ogg, flac, mp4/m4a, aac, mkv/webm), never as playlists or scripts that point at other files.
- Without `--out`, `output_dir` from a spec or project config must stay inside the spec folder, the current folder, or an `--allow-path` folder.
- Voiceover: the text-to-speech server address is a user-config / command-line setting only, so a spec cannot make yamlreel send its text elsewhere. Whether narration text leaves your machine depends on the server you configure: a local server keeps it local, a remote URL receives it. Server replies are size-capped and must be valid PCM WAV before they are used.
- Specs, configs, text, scene counts, durations, image sizes and viewport sizes are bounded, and unknown spec keys are errors. The absolute limits hold whatever a spec or config sets: 3600 seconds and 1000 scenes (`limits` values above these are capped), `MAX_FRAMES` (216,000 frames: seconds x fps x formats), `MAX_CAPTURE_PIXELS` (36,000,000 device pixels per capture; taller full-page captures are trimmed), and per-diagram caps on nodes, edges and flashes.

Not covered: a malicious `chromium_path`, ffmpeg binary or font file you chose yourself (yamlreel runs the `ffmpeg` on your PATH, else the one from the `imageio-ffmpeg` package or its `IMAGEIO_FFMPEG_EXE` variable; none of these can come from a spec), and a spec kept in a very broad folder (your home directory, `/tmp`), because the spec's own folder is readable. Render specs you do not trust inside a container or VM with no access to internal networks.

Report vulnerabilities privately through GitHub's "Report a vulnerability" button on the Security tab (private vulnerability reporting), or to the repository owner.
